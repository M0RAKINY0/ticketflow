# Task 2: Authentication, Refresh Rotation, and Role Authorization Implementation Plan

> **For agentic workers:** Implement this plan test-first. Each behavior must be observed failing before its production code is written.

**Goal:** Provide secure registration, login, refresh-token rotation, logout, authenticated profile access, and admin-controlled role assignment.

**Architecture:** Route modules validate HTTP payloads and delegate to focused services. Services enforce business and security rules while repositories isolate Prisma persistence. Stateless access JWTs carry user ID and role; opaque refresh tokens are hashed before storage and transactionally replaced on use.

**Tech Stack:** Express 5, TypeScript, Zod 4, Prisma 7/PostgreSQL, bcrypt, jsonwebtoken, Vitest, Supertest.

## Requirements and exact values

- Password hashing uses bcrypt cost `12`.
- Access JWTs contain `sub` and `role` and expire after `15 minutes`.
- Refresh tokens are generated by `randomBytes(48)`, stored only as a SHA-256 hash, and expire after `30 days`.
- Refresh-token rotation is transactional and rejects expired, revoked, and reused tokens with `401`.
- Public registration always creates a `USER`, regardless of a supplied role.
- Role updates are admin-only and may assign only `USER` or `ORGANIZER`.
- Successful auth endpoints alone return access and refresh tokens; password hashes never appear in responses.

## Files and responsibilities

- `src/utilities/token.ts`: JWT creation/verification and opaque refresh-token lifecycle.
- `src/services/auth.ts`: password hash/compare utilities.
- `src/modules/auth/auth.schema.ts`: request-body validation schemas.
- `src/modules/auth/auth.repository.ts`: user and refresh-token persistence operations.
- `src/modules/auth/auth.service.ts`: registration, login, refresh, and logout workflows.
- `src/modules/auth/auth.routes.ts`: public authentication routes.
- `src/modules/users/users.repository.ts`: user lookup and role updates.
- `src/modules/users/users.service.ts`: profile retrieval and restricted role changes.
- `src/modules/users/users.routes.ts`: authenticated user routes.
- `src/shared/auth.ts`: bearer-token authentication and role middleware.
- `src/app.ts`: module-route registration and centralized error response.
- `tests/unit/token.test.ts`: token signing and refresh lifecycle behavior.
- `tests/integration/auth.test.ts`: HTTP authentication and authorization contracts.

## Acceptance checklist

- [ ] Public registration ignores an incoming role and returns a safe user payload.
- [ ] Login supplies a valid token pair; bad credentials receive `401`.
- [ ] Refresh rotation revokes the old record atomically and a reused raw token receives `401`.
- [ ] Logout makes its refresh token unusable.
- [ ] Authenticated users can read `/api/v1/me`; absent/invalid bearer credentials receive `401`.
- [ ] Only admins can change a user to `USER` or `ORGANIZER`; forbidden callers receive `403`.
- [ ] No response serializes `passwordHash`.
