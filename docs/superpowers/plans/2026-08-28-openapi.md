# OpenAPI documentation implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a unified, testable OpenAPI 3.1 contract and Swagger UI for every Ventra backend endpoint.

**Architecture:** Better Auth generates its own schema. Ventra maintains a typed application document and merges the two at request time, then serves JSON and Swagger UI through Express.

**Tech Stack:** Express, Better Auth OpenAPI plugin, OpenAPI 3.1, Swagger UI Express, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-28-openapi-design.md`

## Global constraints

- Document the current API only.
- Keep non-docs security headers unchanged.
- Tests must fail when a registered Ventra route is absent from the contract.

### Task 1: Documentation dependencies and auth schema

- [ ] Add failing tests for generated Better Auth OpenAPI paths.
- [ ] Enable Better Auth's OpenAPI plugin without its separate UI.
- [ ] Install Swagger UI Express and types.

### Task 2: Ventra contract

- [ ] Add failing coverage tests for every health, user, and ticketing route.
- [ ] Create schemas, security definitions, parameters, examples, and operations in `src/infrastructure/openapi.ts`.
- [ ] Merge Better Auth paths and components without overwriting Ventra definitions.

### Task 3: HTTP documentation routes

- [ ] Add failing tests for `/api/openapi.json`, `/api/docs`, and docs-only CSP.
- [ ] Create `src/routes/docs.routes.ts` and mount it before the application router.
- [ ] Verify JSON and HTML responses.

### Task 4: Documentation and verification

- [ ] Update README with documentation URLs.
- [ ] Run full tests, type checking, build, changed-file formatting, and `git diff --check`.
- [ ] Commit the implementation on `doc-branch`.
